# Maintainership and decisions

[Nir Rozen (@MrQuality)](https://github.com/MrQuality) is the current sole maintainer.
Contributors are welcome; contribution does not automatically grant repository access
or a commitment to merge a proposal. There is no formal foundation, steering committee
or guaranteed maintenance schedule.

Use issues for concrete bugs and feature proposals, and Discussions for questions and
early design ideas. Explain the user need, acceptance criteria, compatibility implications
and relevant security/performance evidence. The maintainer makes final scope and release
decisions after considering discussion and the [roadmap](ROADMAP.md).

Changes enter `main` through pull requests with successful required CI and resolved
review conversations. The required approving-review count is **zero**, allowing the sole
maintainer to merge their own work. Independent reviews remain welcome. Force pushes and
branch deletion are blocked, including for administrators. Small commits with contextual
messages are preferred; merge commits preserve those messages. See [CONTRIBUTING.md](CONTRIBUTING.md).

New maintainers or changes to this policy should be proposed in a public pull request.
Follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) in all project spaces and use
[SECURITY.md](SECURITY.md) for private vulnerability reporting. Apache-2.0 licensing and
third-party notice obligations apply as documented in [LICENSE](LICENSE) and [THIRD_PARTY.md](THIRD_PARTY.md).
